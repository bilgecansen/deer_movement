simulate_movement() — function explanation

How a single simulated trajectory is produced from a fitted iSSF and an environmental raster stack, with a fast path for models that don't need monthly NDVI updates.

Contents: Role · Signature · Two paths · Walkthrough · NDVI detection · Kernel structure · Subtle behaviors

Role in the pipeline

simulate_movement() produces one simulated trajectory of a deer across the same time window the observed track covers. Higher up in run_sims_issf.R, this function is called n_sim times per model per deer, building an ensemble of replicate paths.

The function walks burst-by-burst (continuous GPS sequences). Within a burst it either runs a single kernel (when the model has no NDVI terms) or walks month-by-month (when NDVI matters), swapping in the appropriate monthly NDVI layer before building each kernel.

Signature

simulate_movement <- function(
  stp_data,    # observed step data (drives timing + burst structure)
  env_test,    # SpatRaster stack with every layer the model formula uses
  ndvi_test,   # 12-layer SpatRaster (monthly NDVI) — ignored if model has no NDVI
  issf_train   # fitted iSSF (made by amt::make_issf_model)
)

No spatial covariate computation happens in this function. The caller (run_sims_issf.R) loads HR_edge, HR_center, HR_center_log, etc. onto env_test before invoking, so this function never has to know which covariates exist.

Two code paths

PathWhen takenCost per burst
NDVI Model has any coefficient name containing "ndvi" One kernel build per month (~4–10 builds for a season-long burst)
Simple Model has no NDVI coefficients One kernel build per burst

Both paths share an identical covariate-extraction callback (cov_fun) hoisted to a single local definition. They differ only in whether they decompose the burst by month and refresh env_test$ndvi.

NDVI detection

needs_ndvi <- any(grepl(
  "ndvi",
  names(issf_train$model$coefficients),
  ignore.case = TRUE
))

Cheap, robust, and self-contained. The model carries its own metadata about whether NDVI matters, so the caller doesn't need to know.

Walkthrough

Setup

data_step <- stp_data
bursts    <- unique(data_step$burst_)

Bursts are continuous GPS sequences separated by data gaps. Simulating burst-by-burst gives two benefits:

  • No need to invent inter-burst connectivity across GPS dropouts.
  • Each burst re-anchors on observed truth at its start, so simulated drift can't compound across the whole season.

Covariate callback (shared by both paths)

cov_fun <- function(xy, map) {
  xy |>
    amt::extract_covariates(map, where = "both") |>
    amt::time_of_day(include.crepuscule = FALSE, where = "both") |>
    dplyr::mutate(
      tod_start_day   = as.integer(tod_start_ == "day"),
      tod_start_night = as.integer(tod_start_ == "night"),
      days = lubridate::yday(t2_) - min(lubridate::yday(t2_)) + 1
    )
}

This is what amt calls at every candidate step the redistribution kernel considers. It pulls every layer in map at the candidate's start and end (producing columns like HR_edge_start, ndvi_end, etc.), tags day/night, and adds a within-burst days counter.

NDVI path

burst_data$month_group <- lubridate::month(burst_data$t1_)
months <- unique(burst_data$month_group)
sim_burst <- NULL

for (mo in months) {
  mo_data <- burst_data |> dplyr::filter(month_group == mo)
  n_steps <- nrow(mo_data)

  # 1. Swap in this month's NDVI layer
  env_test$ndvi <- terra::resample(ndvi_test[[mo]], env_test, method = 'near')

  # 2. Pick a starting point
  if (is.null(sim_burst)) {
    # First month: anchor on observed (x1_, y1_, t1_)
    start_row <- mo_data[1, c('x1_', 'y1_', 't1_')]
    start_pt  <- amt::make_track(start_row, .x = x1_, .y = y1_, .t = t1_,
                                  crs = terra::crs(env_test))
  } else {
    # Subsequent months: continue from last simulated point
    start_row <- sim_burst[nrow(sim_burst), ]
    start_pt  <- amt::make_track(start_row, .x = x_, .y = y_, .t = t_,
                                  crs = terra::crs(env_test))
  }
  start_pt <- start_pt |> amt::make_start() |> amt::mutate(dt = lubridate::hours(4))

  # 3. Build kernel + draw n_steps
  kernel     <- amt::redistribution_kernel(x = issf_train, map = env_test,
                                            fun = cov_fun, start = start_pt,
                                            landscape = "discrete", as.rast = FALSE)
  sim_result <- tryCatch(amt::simulate_path(kernel, n = n_steps),
                          error = function(err) NA)
  if (any(is.na(sim_result))) return(NULL)

  sim_burst <- dplyr::bind_rows(sim_burst, sim_result |> dplyr::select(x_, y_, t_))
}

sim_burst |> dplyr::mutate(burst_ = b)

Notes specific to this path:

  • The trajectory is continuous within a burst — month boundaries only refresh NDVI; they do not reset to truth.
  • terra::resample(..., method = 'near') is appropriate for NDVI because nearest-neighbor preserves sharp habitat edges.
  • If simulate_path errors mid-burst, the return(NULL) drops the whole burst from this simulation. Other bursts are independent.

No env_test$ndvi assignment, no inner loop. One kernel build, one simulate_path call, all steps in the burst at once.

Inside the kernel construction

kernel <- amt::redistribution_kernel(
  x          = issf_train,
  map        = env_test,
  fun        = cov_fun,
  start      = start_pt,
  landscape  = "discrete",
  as.rast    = FALSE
)
x The fitted iSSF — supplies coefficients, the gamma step-length distribution, and the von Mises turning-angle distribution.
map The env raster stack. Every layer here becomes available to cov_fun.
fun Called by amt at every candidate step to produce the design-matrix row the kernel scores against the model coefficients.
start 1-row track giving the kernel its anchor and timestep.
landscape = "discrete" Discretizes candidate space onto the raster grid. Appropriate when env is rasterized.
as.rast = FALSE Returns the kernel as an internal amt object (we only need to draw from it; no need to inspect per-cell weights).

Subtle behaviors worth remembering

Re-anchoring at burst boundaries. Simulated drift accumulates only within a burst — between bursts we re-anchor on the observed start point.
Re-anchoring at month boundaries (NDVI path only). Within a burst, the trajectory is continuous: kernel rebuilds happen at month boundaries, but the position continues from the previous simulated point.
Failure mode propagation. If simulate_path errors inside any month of a burst, the return(NULL) drops the entire burst from this simulation. This is intentional — partial bursts are harder to reason about than missing bursts. Other bursts proceed unaffected.
Kernel-rebuild cost. NDVI path: roughly one rebuild per month per burst (typically 4–10 rebuilds per season). Simple path: one rebuild per burst, full stop. For models without NDVI, the simple path is the cost reduction this dual-path design exists for.
Caller contract. env_test must already carry every layer the model formula references. If the formula uses HR_edge_end and the layer is absent, the kernel will silently produce no HR_edge_* column, the design-matrix row will be missing that column, and amt's scoring may either error or produce wrong values. run_sims_issf.R handles this correctly today by adding HR_edge / HR_center / HR_center_log layers before calling.

What changed from the previous version

Previously the function unconditionally walked month-by-month, even for models without any NDVI terms. This version keeps that path when needed and adds a simple "one kernel per burst" path otherwise. Detection is automatic via inspection of the fitted model's coefficient names.

No change to the function signature; no change to the caller. Only the internal branching is new.
