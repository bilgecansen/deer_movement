Deer movement pipeline — overview

Five stages from raw GPS tracks to skill-scored model comparisons. Every per-deer artifact is keyed by <id>_<season>_<year>.

Contents: High-level overview · Detailed flow · Stage 1 — Data prep · Stage 2 — Fitting · Stage 3 — Simulation · Stage 4 — Skill evaluation · Stage 5 — Aggregation · Filesystem layout · Run order · Utilities

High-level overview

The pipeline is a directed chain: each stage consumes the previous stage's outputs (plus any external rasters it needs). All stages support resumable reruns and have an overwrite flag to refresh.

Stage 1 — Data preparation

Convert raw inputs into per-deer wrangled track files keyed by (id, season, year). The four scripts run roughly independently apart from create_hr_rasters.R → wrangle_deer_mvt.R: HR rasters must exist before per-deer track wrangling can extract their values into the design matrix.

Stage 2 — Model fitting

Fit 10 candidate iSSF formulas to each deer's design matrix. fit_mod() wraps each fit in tryCatch, so a single formula failing on a single deer doesn't kill the deer's run — the failure is recorded as a status object inside the saved list.

ScriptInputsOutputsNotes
fit_issf.R data/tracks/data_<key>.rds results/issf/results_issf_<key>.rds
list of 10 (iss, coeff, aic) entries 		Loops in R over data/tracks/ contents. overwrite flag at top.

Formulas reference: HR_edge_*, HR_center_log_*, wiscland_*, ndvi_*, tod_start_, plus movement terms (log(sl_), cos(ta_)). No model uses HR_bin_* in the current set.

Stage 3 — Simulation

For each deer, draw n_sim = 10 simulated paths from each fitted model's redistribution kernel. Models are simulated in parallel via furrr::future_map; NDVI-using models take a month-by-month loop; non-NDVI models take a one-kernel-per-burst fast path (auto-detected via all.vars(formula)).

Run order recipe

From a clean slate, in order:

# Stage 1 — data prep (only re-run if raw inputs change)
Rscript scripts/combine_ndvi.R       # one-time
Rscript scripts/wrangle_wiscland.R   # one-time
Rscript scripts/create_hr_rasters.R  # loops in R
Rscript scripts/wrangle_deer_mvt.R   # loops in R

# Stage 2 — fit
Rscript scripts/issf/fit_issf.R           # loops in R

# Stage 3 — simulate
bash scripts/issf/run_sims_issf_all.sh    # iterates every deer with issf

# Stage 4 — evaluate (any order; all three independent)
bash scripts/issf/run_logscore_issf_all.sh
bash scripts/issf/run_udoverlap_issf_all.sh
Rscript scripts/issf/compute_es_issf.R

# Stage 5 — aggregate
Rscript scripts/issf/filter_models_issf.R

All loops/wrappers skip already-completed deer by default. Any of them can be forced to re-run with --overwrite (bash) or by flipping overwrite <- TRUE at the top of the R script.

Conventions to keep in mind

  • Deer key: <id>_<season>_<year> (e.g. 5000_fa_2017). Filenames everywhere downstream are built from this.
  • Filtering criterion: keep & !excursion & !unstable_hr_center & year %in% 2017:2021. Identical between create_hr_rasters.R and wrangle_deer_mvt.R — keep them in sync if you change either.
  • CRS: working CRS is EPSG:6610 (UTM-style equal-area for Wisconsin). NDVI/AKDE machinery transits through 4326 internally and transforms back as needed.
  • Failure containment: every loop wraps per-deer work in tryCatch so one bad deer doesn't halt a batch. Inside fit_issf.R, fit_mod additionally returns failure-status objects per formula so partial deer are saved.
  • Resumability: every batch script checks file.exists() before running and skips done deer unless overwrite is set. Reruns of an interrupted batch pick up where they left off.
